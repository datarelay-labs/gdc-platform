Version 1.0

Status: Implementation Ready

# Purpose

본 문서는 Stream Wizard의 Sample & Record Selection 단계에서 생성되는 Union Schema의 생성 규칙과 Route Processing(Transform concern) 표시 방식을 정의한다.

목적은 다음과 같다.

```text
단일 이벤트 기반 Mapping 제거

↓

다수 이벤트 기반 Union Schema 생성

↓

희귀 필드 발견

↓

민감 필드 발견

↓

Transform 정확도 향상
```

---

# Product Principle

Data Relay는

```text
Data Delivery Gateway
```

이다.

따라서

```text
새 필드를 숨기지 않는다.

새 필드를 제거하지 않는다.

최대한 많은 필드를 보여준다.
```

---

# Union Schema Definition

Union Schema는

테스트 과정에서 수집된 모든 이벤트의 필드 집합이다.

예

Event 1

```json
{
  "user":"aaa"
}
```

Event 2

```json
{
  "user":"bbb",
  "email":"bbb@test.com"
}
```

Event 3

```json
{
  "user":"ccc",
  "phone":"010"
}
```

생성 결과

```text
user

email

phone
```

# Acceptance Criteria

```text
1. API Test 시 10~20 이벤트 분석

2. Event Root 기준 Union Schema 생성

3. Transform Tree는 Union Schema 기반

4. 필드 출현 빈도 표시

5. Rare Field 표시

6. Sensitive Suggestion 표시

7. 샘플 값 표시

8. Add Field와 공존

9. Unknown Field Pass-through 유지

10. 기존 Mapping Runtime 변경 없음
```

# Route Architecture Extension

Data Relay 기본 아키텍처

```text
One Stream
↓
Many Routes
↓
Many Destinations
```

---

Union Schema는

Route Processing의 공통 입력이다.

---

동일 Stream의 모든 Route는

동일 Union Schema를 공유한다.

---

Destination별 처리를 위해

별도 Union Schema를 생성하지 않는다.

---
