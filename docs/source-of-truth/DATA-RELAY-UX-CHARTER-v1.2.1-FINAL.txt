# DATA-RELAY-UX-CHARTER
Version 1.1

Purpose

이 문서는 Data Relay의 UX 설계 기준 문서이다.

UI를 만들기 전에

- 사용자가 누구인가
- 사용자가 무엇을 하는가
- 무엇을 먼저 보여줘야 하는가
- 어떤 정보는 숨겨야 하는가

를 정의한다.

==================================================
1. Product Mental Model
==================================================

Data Relay는

Data Delivery Gateway

+

Optional Data Protection

제품이다.

--------------------------------------------------

사용자 목적

1. 데이터를 가져온다

2. 데이터를 변환한다

3. 데이터를 목적지로 보낸다

4. 문제가 없는지 확인한다

5. 필요하면 보호한다

--------------------------------------------------

Data Relay는

Governance Product가 아니다.

Governance는 부가 기능이다.

==================================================
2. User Mental Model
==================================================

사용자는

아래 순서로 생각한다.

1. 데이터가 들어오는가

2. 데이터가 나가는가

3. 문제가 있는가

4. 왜 문제가 있는가

5. 어떻게 해결하는가

--------------------------------------------------

사용자는

아래 개념으로 생각하지 않는다.

- Schema Drift
- Replay
- Quarantine
- Failover
- Classification
- Policy Engine
- Protection Engine
- Runtime Engine

--------------------------------------------------

사용자는

아래 개념으로 생각한다.

- 데이터 안 들어옴
- 데이터 적게 들어옴
- 데이터 안 나감
- 데이터 구조 바뀜
- 개인정보 발견됨

23. UX Golden Rules
==================================================

Rule 1

사용자는 엔진을 보지 않는다.

==================================================

Rule 2

Dashboard는 원인을 보여주지 않는다.

==================================================

Rule 3

Dashboard는 문제만 보여준다.

==================================================

Rule 4

원인은 Drill Down 후 보여준다.

==================================================

Rule 5

운영 단위는 Stream Group이다.

==================================================

Rule 6

Stream Group은 Source Product 기준이다.

==================================================

Rule 7

Flow 생성보다 운영이 중요하다.

==================================================

Rule 8

Data Protection은 중요하지만
Data Delivery가 우선이다.

==================================================

Rule 9

What happened?

↓

Where?

↓

Why?

↓

What should I do?

순서를 반드시 지킨다.

==================================================

Rule 10

Alert는 메뉴가 아니다.

==================================================

Rule 11

Activity는 Dashboard가 아니다.

==================================================

Rule 12

Stream Group은 메뉴가 아니다.

Streams 화면의 기본 표현 방식이다.

==================================================

Rule 13

사용자는 Stream보다

Source Product를 먼저 인식한다.

==================================================

Rule 14

Logo Click = Dashboard

==================================================

Rule 15

좌측 메뉴는 최소화한다.

메뉴 수보다

문제 해결 속도가 중요하다.

24. Route Based Delivery Model
==================================================

Data Relay의 기본 아키텍처

One Stream
↓
Many Routes
↓
Many Destinations

==================================================

Route

=

Destination Specific Processing Unit

==================================================

동일 데이터를

목적지별로 전달하기 위해

별도 Stream을 생성해서는 안 된다.

==================================================

목적지별 차이는

Route를 통해 구성한다.
